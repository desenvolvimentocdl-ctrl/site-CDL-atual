Estrutura do projeto

Site em C# sobre .NET 8, dividido em um front-end ASP.NET Core MVC e uma API REST em camadas (Clean Architecture), com banco MySQL 8 acessado pelo Entity Framework Core.

Linguagem
C#

.NET 8 · SDK 8.0.420 (global.json)

Projetos na solução
5

1 front-end e 4 do back-end

Banco de dados
MySQL 8

Base SiteCDL, 5 tabelas

Telas Razor
228

46 institucionais e 161 da Loja

Como as partes conversam

O navegador fala só com o SiteCDL.Web. O Web busca conteúdo na API, que lê o MySQL. Cursos e eventos vêm da Loja, um sistema separado.

Camadas do back-end

Clean Architecture: as dependências apontam para dentro. O Domain não conhece banco nem web.

SiteCDL.Domain

Regras e entidades

Entidades Post, PostCategoria, Paginas, Banner, Home, Search e as interfaces dos repositórios. Sem pacotes externos.

SiteCDL.Application

Casos de uso

Serviços HomeService, PageService, PostService, DTOs, perfil do AutoMapper 13 e utilitários de paginação.

SiteCDL.Infrastructure

Acesso a dados

DataContext e BannerDbContext (EF Core 8.0.10 + Pomelo MySQL 8.0.2), repositórios e 11 migrations do EF.

SiteCDL.API

Entrada HTTP

Controllers Banner, Home, Page e Post, JSON sem conversão de nomes, Swagger em desenvolvimento.

Como rodar localmente

1 · Banco
docker compose up -d
2 · API
dotnet run --project Backend/SiteCDL.API
3 · Site
dotnet run --project Frontend/SiteCDL.Web

Endereço da API configurável por ApiBaseUrl; padrão http://127.0.0.1:7110/api/.

Pontos de atenção

Itens herdados do código original que convém tratar nas próximas etapas.

Alta

Credenciais no repositório

Senhas do MySQL no docker-compose.yml e token da API da Loja escrito nos controllers. Mover para variáveis de ambiente ou User Secrets e trocar as senhas.

Média

Sem testes automatizados

O projeto de testes nunca foi versionado e saiu da solução. Vale começar por testes da API e das rotas de GEO.

Média

CORS aberto

O site aceita qualquer origem (AllowAnyOrigin). Restringir ao Portal e à Loja.

Média

Acesso duplicado ao banco

O Web tem DataContext e repositórios próprios além da API. O ideal é concentrar o acesso na API.

Média

Publicação sem pipeline

O Dockerfile do Web está comentado e não há CI de build. A esteira desta apresentação é o primeiro workflow do repositório.

Info

Painel é demonstração

Login e dados do Painel do Associado são fictícios. Ligar a uma base real exige autenticação de verdade.
